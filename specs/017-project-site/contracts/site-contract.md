## Page rules

- Every guide has frontmatter with `title`, `description` and `sidebar.order`; the sidebar of each section is generated from the files.
- Links between guides are relative `.md` links (they work on GitHub); the build rewrites them to site URLs and fails if the target is missing.
- Links to code, specs or configuration samples use absolute `https://github.com/jircd/jircd-server/blob/main/...` URLs.
- A guide states what the code does today; it does not describe planned behaviour. Anything unimplemented found during migration becomes an issue, not prose.

## API reference

- Published at `/api/`, output of `./gradlew extensionApiJavadoc` (directory `build/docs/extension-api`).
- Packages (decided scope): `net.jircd.core.extension`, `net.jircd.core.extension.capability`, `net.jircd.protocol`, plus only the packages T016 finds necessary for links from those to resolve (recorded here by T016).
- The task is part of `./gradlew build` (`check` depends on it): a Javadoc error fails CI and local builds.

## Workflow contract (`.github/workflows/pages.yml`)

| Event | Jobs | Publishes |
| --- | --- | --- |
| `pull_request` touching `docs/**`, `site/**`, `jircd-core/src/main/java/**`, `jircd-protocol/src/main/java/**`, `build.gradle.kts` or the workflow | `build` | no |
| `push` to `main` with the same paths | `build`, `deploy` | yes |
| `workflow_dispatch` on `main` | `build`, `deploy` | yes |
| `workflow_dispatch` on another branch | `build` | no (`deploy` skipped) |

- The `deploy` job carries `if: github.ref == 'refs/heads/main' && github.event_name != 'pull_request'`.
- Permissions: `contents: read` by default; `pages: write` and `id-token: write` only on the deploy job.
- Every action pinned by full commit SHA with the tag in a comment; Node version from `site/.nvmrc`.
- A broken link, a Javadoc error or an Astro build error fails `build` and so the PR; `deploy` is skipped.
- `concurrency` group `pages`, no cancellation of a running deployment.

## Dependabot

`npm` ecosystem, directory `/site`, weekly, minor and patch updates grouped, at most 2 open PRs.

## README contract

About 100 lines: badges (kept), description, quick start (container; standalone build), how to connect, links to the site and each guide section, contributing, security, licence. No configuration reference.
